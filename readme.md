1주차 활동 내용 (기초 이론 및 기본 틀 잡기)

이번 주차는 본격적인 개발에 앞서 웹 서버의 동작 방식과 AI 연동을 위한 이론적 뼈대를 탄탄하게 다지는 데 집중했습니다.
• 웹 서버 및 API 기초 이론 학습
 클라이언트-서버 구조 이해: 사용자가 웹 브라우저(클라이언트)를 통해 요청을 보내면, 파이썬으로 구축할 백엔드(서버)가 데이터를 처리하고 응답하는 전체적인 데이터 흐름을 학습했습니다.
 REST API의 개념 파악: 프론트엔드와 백엔드가, 그리고 백엔드와 외부 LLM(OpenAI 등)이 어떻게 데이터를 주고받는지(GET, POST 등의 통신 규약) 그 원리를 숙지했습니다.
 서버 인프라 기초: 로컬(내 컴퓨터) 환경과 클라우드(24시간 돌아가는 외부 서버) 환경의 차이점을 비교하며, 향후 배포를 위한 기초 지식을 다졌습니다.

• 기본 개발 환경 구축
 학습한 이론을 바탕으로 아주 기초적인 실습 환경을 세팅했습니다. 파이썬 가상환경(Virtual Environment)을 생성해 프로젝트 독립성을 확보하고, 기초 뼈대 코드를 작성해 내 컴퓨터에서 로컬 서버가 정상적으로 켜지는지 가볍게 테스트를 완료했습니다.

소감: 이번 주차는 무작정 코드를 치기보다는, 앞으로 만들 AI 가계부가 어떤 원리로 돌아가는지 전체적인 숲을 보는 데 집중했다. C언어나 자바를 배웠을 때와 달리, 웹 서버가 클라이언트와 어떻게 통신하고 LLM API를 어떤 방식으로 호출하는지 그 '기초 이론'을 이해하는 것이 무엇보다 중요하다고 느꼈다.

2주차 활동 내용 (데이터베이스 연결 및 API 테스트)
이번 주차는 서버에 실제 데이터를 영구적으로 저장하고 불러오는 데이터베이스 연동 기초를 실습했습니다.

SQLite 데이터베이스 연동: 파이썬 내장 DB인 SQLite를 활용해 서버를 껐다 켜도 데이터가 유지되도록 가계부 파일을 생성하고 서버와 연결했습니다.

API 엔드포인트 구축: 사용자의 수입/지출 내역을 서버로 보내 저장하는 기능인 POST 요청과, 저장된 전체 내역을 서버에서 읽어오는 기능인 GET 요청을 코드로 구현했습니다.

자동 생성 웹 UI를 통한 즉각적인 테스트: 별도의 프론트엔드 코드를 짜지 않고도, FastAPI가 자동으로 제공하는 API 테스트 웹페이지(/docs)에 접속해 기능들을 테스트했습니다.

- 2주차 소감
이번 주는 다른 일정들이 많아 프로젝트에 긴 시간을 투자하지는 못했다. 그래서 데이터베이스를 연결하는 아주 기본적인 뼈대 코드만 작성해 보았는데, FastAPI가 자동으로 만들어주는 테스트 웹사이트 덕분에 내가 짠 코드가 어떻게 작동하는지 화면으로 바로바로 확인할 수 있었다. 보통 백엔드나 서버 설정이라고 하면 까만 터미널 창만 보고 있어야 해서 지루할 줄 알았는데, 내가 입력한 내역이 웹 화면을 거쳐 실제 데이터베이스 파일에 저장되고 다시 불러와지는 과정을 즉각적으로 눈으로 보니 흥미가 확 생기고 정말 재미있었다. 비록 많은 분량을 소화하진 못했지만 백엔드 개발의 재미를 확실히 느낄 수 있었던 시간이었다.

3주차 활동 내용 - LLM API 연동 및 AI 분석 기능 구현
이번 주는 서버에 저장된 데이터를 바탕으로 AI가 소비 패턴을 분석해 주는 가계부의 핵심 기능을 구현했습니다.

무료 AI API 도입: 과금이 발생하는 서비스 대신, 개발자에게 넉넉한 무료 사용량을 제공하는 구글의 Gemini API(gemini-3.5-flash 모델) 키를 발급받아 프로젝트 환경에 연동했습니다.

데이터 기반 프롬프트 엔지니어링: 2주 차에 구성한 SQLite 데이터베이스에서 가계부 내역인 수입/지출, 금액, 내역을 불러와, AI에게 질문할 자연스러운 문장으로 자동 조립하는 파이썬 로직을 작성했습니다.

API 통신 및 결과 확인: 서버 코드 내에서 구글 AI 모델로 분석 요청을 보내고, 도출된 절약 팁과 분석 결과를 FastAPI의 자동 테스트 UI(/docs)를 통해 성공적으로 확인했습니다.

= 3주차 소감
본격적으로 AI를 서버에 붙이는 3주차 작업을 진행했다. 처음에는 API 키를 등록하고 결제를 해야 한다는 사실에 멈칫했지만, 구글 Gemini라는 훌륭한 무료 대안을 찾아 적용하는 방법을 배웠다. 긴 API 키를 코드에 넣고 다루는 과정이 조금 낯설었지만, 내가 DB에 입력해 둔 '국밥' 같은 실제 지출 데이터가 코드를 통해 AI에게 전달되고, AI가 그 데이터를 분석해 나만의 맞춤형 절약 팁을 반환해 주는 것을 보니 무척 신기했다. 'AI 서비스'라는 것이 마법 같은 게 아니라, 결국 잘 정리된 내 데이터를 API를 통해 AI 모델과 주고받는 논리적인 과정이라는 것을 몸소 깨달은 알찬 시간이었다.

4주 차 활동 내용
사용자 인터페이스 구축: HTML과 CSS를 활용하여 수입/지출 내역을 입력하는 폼과, 저장된 데이터를 리스트로 보여주는 직관적인 웹 화면을 구성했습니다.

클라이언트-서버 통신 구현: JavaScript를 사용하여 사용자가 화면에서 버튼을 클릭했을 때 FastAPI 서버의 엔드포인트로 데이터를 주고받는 비동기 통신 로직을 작성했습니다.

풀스택 파이프라인 완성: 웹 브라우저 ➔ FastAPI 서버 ➔ SQLite DB ➔ Google Gemini AI ➔ 웹 브라우저로 이어지는 전체 서비스 흐름이 정상적으로 렌더링 되는지 통합 테스트를 완료했습니다.

- 4주 차 소감
사람들이 실제로 사용할 수 있는 형태의 '웹 화면'을 만들었다는 점에서 가장 성취감이 큰 한 주였다. 프론트엔드 코드와 백엔드 코드를 연결하는 과정이 헷갈렸지만, 버튼을 눌렀을 때 화면 새로고침 없이 AI가 내 소비 패턴을 분석해 화면에 텍스트를 띄워주는 모습을 보니 그동안 고생하며 서버 뼈대와 DB를 세팅했던 것들이 완벽하게 보상받는 기분이었다. 이제 제대로 된 웹 서비스의 형태를 갖췄으니, 다음 주에는 배포할 수 있도록하여 내 컴퓨터가 아닌 진짜 인터넷 주소로 접속하도록 구현할 것이다.

6주 차 활동 내용 (디자인 고도화 및 서비스 모니터링)
이번 주차는 배포된 기본 서비스의 퀄리티를 한 단계 끌어올리고, 실제 백엔드 운영자 입장에서 서버 상태를 점검하며 다음 버전 업데이트를 기획하는 데 집중했습니다.

UI/UX 디자인 전면 개편: 모던 스타일을 채택하여 가계부 화면을 새롭게 디자인했습니다. 오픈소스 웹 폰트를 적용하고 여백과 색상을 세련되게 다듬었으며, 입력창과 버튼에 상호작용(CSS 애니메이션)을 추가해 사용자 편의성을 크게 높였습니다.

백엔드 실시간 로그 모니터링: Render 클라우드 대시보드의 실시간 로그 뷰어를 활용하여, 프론트엔드에서 데이터 저장 요청이 넘어올 때 백엔드 서버가 실시간으로 어떻게 응답하는지, 오류 없이 트래픽을 처리하는지 직접 추적하고 검증했습니다.

6주 차 최종 소감
방학이라는 짧고 압축적인 일정 속에 달려온 끝에 드디어 나만의 'AI 가계부' 웹 서비스를 완성하고 클라우드 배포까지 마쳤다. 이번 프로젝트에서 가장 큰 고비는 프론트엔드와 백엔드를 연결하는 비동기 통신 과정이었다. 또한, 구글 API 키 환경 변수 처리와 클라우드 서버의 DB 독립 생성 원리를 겪으며 실무적인 보안과 서버 아키텍처의 기본을 깨달았다.
배포 이후에는 Render 대시보드에서 실시간 로그 모니터링을 진행하며 백엔드 개발자의 핵심 업무를 직접 체험했다. 보이지 않는 서버 뒤편에서 사용자의 요청 흐름을 실시간으로 추적하고, 만약 발생할지 모르는 DB나 API 통신 문제의 원인을 즉각적으로 파악해 서비스 안정성을 방어하는 것이 왜 백엔드의 가장 중요한 역할인지 분명히 이해할 수 있었다.
다만 방학 동안 짧은 기간에 핵심 기능 위주로 단순하게 구축하고 실제 사용 시간도 길지 않다 보니, 치명적인 오류 상황을 겪고 치열하게 트러블슈팅을 해볼 기회가 없었던 점은 못내 아쉽다. 하지만 이번 프로젝트를 끝이 아닌 시작점으로 삼아, 앞으로는 날짜별 소비를 한눈에 볼 수 있는 달력 UI가 포함된 버전 2, 나아가 버전 3까지 꾸준히 서비스를 고도화해 나갈 계획이다. 그 과정에서 필연적으로 마주할 수많은 버그와 오류들을 내 손으로 직접 찾아내고 수정하며 멈추지 않고 성장하는 개발자가 되고 싶다.
